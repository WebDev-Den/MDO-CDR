# mdo_cdr

Програмний засіб контрольованого реконструювання мультимедійних цифрових об'єктів для захисту кінцевих пристроїв.

Розроблено в межах дисертаційного дослідження на тему «Інформаційна технологія контрольованої структурної перебудови мультимедійних цифрових об'єктів для захисту кінцевих пристроїв».

Засіб реалізує конвеєр Content Disarm & Reconstruction (CDR). Вхідний мультимедійний файл розбирають, з нього вилучають підтверджені структурні елементи та формують нове байтове подання. Метадані, приховані структури й елементи, що не відповідають правилам допустимого подання, до виходу не потрапляють.

## Підтримувані формати

| Формат | Спосіб оброблення |
|---|---|
| PNG, JPEG, WebP, BMP, TIFF | Розкодування до пікселів, повторне кодування. EXIF, XMP, ICC — вилучаються |
| GIF | Покадрове розкодування, нормалізація затримок (мінімум 20 мс) |
| APNG | Обхід чанків PNG, валідація CRC-32, вилучення tEXt, iCCP, eXIf |
| MP3 | Вилучення тегів ID3v1, ID3v1.1, ID3v2; перевірка кадрів MPEG |
| WAV | Обхід блоків RIFF, збереження fmt і data, решта — вилучається |
| FLAC | Обхід блоків метаданих, збереження STREAMINFO |
| OGG (Opus, Vorbis) | Обхід сторінок, заміна тегів, перерахунок CRC-32 |
| MP4 / M4A | Рекурсивний обхід атомів ISO BMFF, вилучення udta/meta, перерахунок stco/co64 |
| WebM / Matroska | Обхід елементів EBML, вилучення Tags, Attachments, Chapters |

Файли, що не належать до мультимедійних (PDF, ZIP, виконувані), блокуються.

## Приклад використання

```rust
use mdo_cdr::{
    DefenseContext, FileDefender, SignatureRule,
    policy::{DefensePolicy, ImageOutputFormat},
};

let mut policy = DefensePolicy::default();
policy.image.output_format = ImageOutputFormat::Png;
policy.signature_rules.push(SignatureRule {
    name: "test-signature".to_string(),
    pattern: b"BAD_PAYLOAD".to_vec(),
});

let defender = FileDefender::new(policy);
let result = defender.defend_bytes(
    vec![137, 80, 78, 71],
    Some("upload.png".to_string()),
    DefenseContext::default(),
);

println!("{result:?}");
```

## Конвеєр оброблення

Виклик `FileDefender::defend_bytes` проходить сім етапів:

1. **Класифікація.** Визначення типу файла за байтовими сигнатурами заголовка та розширенням імені. Окрема перевірка подвійних розширень, APNG (чанк `acTL`) та анімованого WebP (прапорець `VP8X`).

2. **Попередня валідація.** Перевірка обсягу вхідних даних та списку заблокованих розширень (28 типів).

3. **Попереднє сигнатурне сканування.** Автомат Ахо-Корасік із 24 базовими правилами: EICAR, PE, ELF, Mach-O, Java class, OLE/CFB, DEX, WASM, скриптові шебанги, архіви.

4. **Перебудова.** Диспетчеризація до обробника за типом. Виклик обгорнуто в `catch_unwind` — збій парсера перетворюється на контрольовану помилку, а не на аварійне завершення.

5. **Валідація виходу.** Перевірка вихідних байтів на заголовки виконуваних файлів (15 сигнатур), відповідність MIME білому та чорному спискам, обмеження обсягу та коефіцієнта розширення.

6. **Повторне сигнатурне сканування.** Той самий автомат Ахо-Корасік по сформованому виходу.

7. **Формування вердикту.** Агрегація повідомлень за трьома вагами: Info (журнал), Warning (підозрілий), Blocking (заблоковано). Нова підстава може лише посилити обмеження.

## Профілі безпеки

- `DefensePolicy::default()` — стандартний
- `DefensePolicy::staging_profile()` — тестове середовище
- `DefensePolicy::strict_profile()` — суворий
- `DefensePolicy::paranoid_profile()` — максимальний

Для багатоорендних систем — `TenantDefenderRegistry` з lock-free читанням, CAS-оновленнями та HMAC-верифікацією.

## Захист від відмов

- Перевірка розмірів зображення до розкодування (захист від декомпресійних бомб)
- Обмеження затримки кадрів GIF (запобігання циклічному DoS)
- Обмеження глибини вкладення контейнерів (MP4 — 32 рівні, 4096 атомів на рівень)
- Обмеження розміру елементів WebM (500 МБ), кількості сторінок OGG (65 536), обсягу WAV (4 ГБ)
- Ізоляція збоїв парсерів через `catch_unwind` — паніка перетворюється на `DefenderError::HandlerPanic`

## Зв'язок з дисертацією та реалізація методів

Програмний комплекс є практичним втіленням результатів розділів 3 і 4 дисертаційної роботи «Інформаційна технологія контрольованої структурної перебудови мультимедійних цифрових об'єктів для захисту кінцевих пристроїв».

### 1. Метод узгодженого попереднього визначення різновиду мультимедійного цифрового об'єкта
* **Теоретична основа (Розділ 3):** оброблення вхідної четвірки $x = \langle b, n, m, c \rangle$, узгодження трьох джерел ознак (ланцюжок розширень імені $n$, заявлений тип $m$ та байтові сигнатури $b$ у вікні $w_f$), блокування попарної розбіжності та вибір параметрів маршруту $\mathcal{R}_1$.
* **Реалізація в кодовій базі:**
  - `src/types.rs`:
    - `FileKind::classify(bytes, name, mime)` — побайтовий аналіз сигнатур (зокрема чанка `acTL` для APNG та прапорця `VP8X` для анімованого WebP) з урахуванням розширення та заявленого MIME.
    - `has_suspicious_double_extension(name)` — виявлення спроб обходу через приховані або подвійні розширення (наприклад, `.exe.png`).
    - `validate_kind_consistency` — перевірка попарної сумісності між категорією за розширенням та категорією за вмістом; несумісність спричиняє негайну помилку блокування.
  - `src/policy.rs`:
    - `DefensePolicy`, `blocked_extensions` — фільтрація небезпечних та заборонених розширень на початковому етапі.
  - `crates/defender-signatures`:
    - `SignatureEngine::scan` — попередній сигнатурний контроль вхідної послідовності (PreScan) автоматом Ахо-Корасік.

### 2. Метод контрольованої багаторівневої перебудови мультимедійних даних
* **Теоретична основа (Розділ 3):** впорядковані рівні реконструювання — структурний $\rho_s$ (перебудова контейнера зі збереженням первинного потоку та перерахунком зміщень і контрольних сум) та змістовий $\rho_m$ (повне розкодування до сирих пікселів/відліків $\mathcal{U}^\oplus$, нормалізація та повторне кодування). Дотримання інваріанта неможливості зниження рівня (non-downgrade invariant).
* **Реалізація в кодовій базі:**
  - **Змістовий рівень $\rho_m$ (розкодування до сирого подання та перекодування):**
    - `src/handlers/image.rs` — повне розкодування зображень (PNG, JPEG, WebP, TIFF, BMP) у растрову матрицю пікселів за допомогою бібліотеки `image`, видалення метаданих (EXIF, XMP, профілів ICC) і кодування в цільовий нормалізований формат. Захист від піксельних бомб через перевірку габаритів до алокації буфера.
    - `src/handlers/gif.rs` — покадрове розкодування анімації, нормалізація часової шкали та клампінг затримки кадрів (`min_frame_delay_cs`) для запобігання DoS-зацикленню.
    - `src/handlers/audio.rs` та `src/handlers/video.rs` — виклики процедур перекодування в еталонні кодеки (MP3, H.264/AAC) за потреби забезпечення змістового рівня.
  - **Структурний рівень $\rho_s$ (нативні контейнерні санітайзери без виклику зовнішніх процесів):**
    - `src/handlers/animated_image.rs` — почанковий обхід структури APNG, перевірка контрольних сум CRC-32 кожного чанка, вилучення небажаних секцій метаданих (`tEXt`, `iCCP`, `eXIf`) зі збереженням кадрів анімації.
    - `src/handlers/mp4_native.rs` — рекурсивний обхід дерева атомів ISO BMFF (MP4/M4A), фільтрація метаданих (`udta`, `meta`, `free`), збереження потоків `mdat` та коригування зміщень у таблицях чанків (`stco`, `co64`).
    - `src/handlers/webm_native.rs` — синтаксичний аналіз елементів EBML (WebM/Matroska) зі змінною довжиною (VINT), видалення блоків тегів і вкладень (`Tags`, `Attachments`).
    - `src/handlers/audio_native.rs` — оброблення MP3 (вилучення ID3v1/ID3v2-тегів), WAV (RIFF-обхід зі збереженням блоків `fmt ` та `data`), FLAC (збереження лише `STREAMINFO`).
    - `src/handlers/ogg_native.rs` — обхід сторінок контейнера Ogg, заміна метаданих коментарів та обов'язковий перерахунок контрольних сум Ogg CRC-32.
  - **Контроль відмов і ресурсоємності:**
    - `src/lib.rs` (`FileDefender::rebuild`) — ізоляція викликів обробників через `std::panic::catch_unwind(AssertUnwindSafe(...))` із трансформацією панік парсерів у `DefenderError::HandlerPanic`.
    - `src/handlers/generic.rs` — розрахунок ентропії Шеннона та блокування не-мультимедійних файлів.

### 3. Метод відокремленої перевірки та монотонного формування рішення про надання
* **Теоретична основа (Розділ 3):** відокремлена перевірка сформованого артефакту, накопичення повідомлень трьох рівнів ваги, монотонне формування висновку та дотримання інваріанта ненадання (Release Invariant): якщо вердикт відмінний від $q_a^D$ («чисто»), результат не надається.
* **Реалізація в кодовій базі:**
  - `src/types.rs`:
    - `AlertSeverity` (`Info`, `Warning`, `Blocking`) — трирівнева шкала вагомості інцидентів та повідомлень.
    - `DefenseVerdict` (`Clean`, `Suspicious`, `Blocked`) — фінальний статус рішення.
    - `DefendedArtifact` — представлення результату, що пов'язує вихідні байти, вердикт, перелік алертів і діагностику.
  - `src/lib.rs`:
    - `validate_output_artifact` — верифікація згенерованої послідовності: блокування появи магічних сигнатур виконуваних файлів (`detect_executable_magic`), контроль допустимих вихідних MIME-типів (`output_mime_whitelist`/`output_mime_denylist`), перевірка максимального обсягу та обмеження коефіцієнта розширення (`max_output_expansion_ratio`).
    - Повторне сканування (PostScan) — повторний прогін автомата Ахо-Корасік по фінальних байтах.
    - `finalize_verdict` — монотонна агрегація алертів: наявність блокувальних повідомлень фіксує вердикт `Blocked`, наявність попереджень — `Suspicious`. Додавання нових повідомлень ні за яких умов не може пом'якшити сформований вердикт.
  - `crates/defender-observability`:
    - `PipelineAuditEvent`, `AuditSink` — простежуваність та незмінність записів аудиту всіх кроків конвеєра.

### 4. Інформаційна технологія та контроль на програмних межах
* **Теоретична основа (Розділ 4):** об'єднання методів у п'ятимодульну інформаційну технологію та відтворення правила ненадання на програмних межах кінцевого пристрою.
* **Реалізація в кодовій базі:**
  - `src/client.rs` (`ClientDefender`) та `src/server.rs` (`ServerDefender`) — реалізація захисного бар'єру на межах прийому/відправлення файлів.
  - `src/ffi.rs` — реалізація зовнішнього програмного C-ABI інтерфейсу передачі унормованих даних і protobuf-метаданих до мобільних і десктопних застосунків.
  - `src/tenant.rs` (`TenantDefenderRegistry`) — модуль керування правилами та конфігураціями: lock-free версіонування через `ArcSwap`, атомарний контроль версій (CAS-оновлення) та перевірка автентичності політик за підписами й HMAC-ключами (`HmacKeyRing`).
