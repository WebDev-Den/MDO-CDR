# Перевірки за вимогами дисертації

Цей розділ пов’язує автоматизовані тести MDO-CDR з вимогами дисертації **«Інформаційна технологія контрольованої структурної перебудови мультимедійних цифрових об’єктів для захисту кінцевих пристроїв»**. Перевірено програмні контракти та критерії збереження вмісту на згенерованих контрольних зразках. Очікування й пороги задано в тестах; фактичні спостереження збережено окремо від них.

## Зафіксована основа

| Поле | Значення |
|---|---|
| Рукопис | `manuscript_Denusiyk_D____20_09_2026.docx` |
| SHA-256 рукопису | `e6dee7339fa2b0c19884b1e44be4a2e41c496f0d514e3da1bdd18b92d1449cc` |
| Основа груп сценаріїв | §4.3, таблиця 4.5: S0–S7 |
| Дослідницькі питання | §4.3, таблиця 4.6: Q1–Q6 |
| Критерії збереження вмісту | §4.6, таблиця 4.11 |
| Назва нової серії | `dissertation-contract-regression` |
| Походження входів | Детерміновані генератори в тестах; для медіа — явно задані параметри FFmpeg |
| Незалежність декодерів | `ND`: процедури окремі, але можуть мати спільні критичні бібліотеки |

Рукопис використано лише як джерело вимог; його вміст не змінено й не скопійовано до репозиторію. Назви груп позначають вид контрольного сценарію, а не заповнення квот основної серії.

Основний набір контрольних записів: [`dissertation_requirements.rs`](../tests/dissertation_requirements.rs). Виміри аудіо й відео: [`dissertation_media.rs`](../tests/dissertation_media.rs). Перевірки реальних EXIF-даних і точних пікселів: [`realworld_simulation.rs`](../tests/realworld_simulation.rs).

BMP і TIFF є додатковими перевірками можливостей продукту: вони не входять до десяти основних різновидів таблиці 3.2 дисертації. Перелік обов’язкових контрольних записів зафіксовано у [`case-plan.json`](case-plan.json); відсутність будь-якого запису завершує серію невдало, навіть якщо решта тестів пройшла.

Позитивні контроли охоплюють усі десять основних різновидів: PNG, JPEG, WebP, GIF, WAV, MP3, FLAC, Opus, MP4 і WebM. Один згенерований контроль на різновид не замінює його вибірку з відкритих джерел.

Повторні запуски не підсумовуються як незалежні спостереження. Основний відтворюваний знімок — запуск із повним охопленням форматів; кожен звіт має власний відбиток перевірених джерел.

У повних Windows- і Linux-запусках виконано 31/31 контрольний сценарій та 197 тестів без помилок. Нормалізовані SHA-256 перевірених джерел збігаються. Для всіх чотирьох аудіоконтролів і двох відеоконтролів відносне відхилення тривалості дорівнює нулю; найменший двонапрямний SI-SDR серед Windows-аудіоконтролів становить 36,621 дБ, найменший середній SSIM двох Windows-відеоконтролів — 0,986646. Повні поканальні та покадрові виміри кожного середовища збережено в його JSON. Контрольні суми завантаженого Linux-артефакту перевірено перед збереженням у Git.

## Правила оцінювання вмісту

- **Зображення:** рівні розміри та точна рівність декодованих пікселів на маршруті з виходом без втрат. Для точно рівних матриць PSNR дорівнює позитивній нескінченності, а не нулю.
- **GIF:** однакові полотна, кількість і порядок кадрів; точна рівність пікселів контрольного зразка; відносне відхилення тривалості кожного кадру та всієї анімації не перевищує 0,02.
- **Аудіо:** однакова кількість каналів; відносне відхилення тривалості не перевищує 0,02; мінімум SI-SDR в обох напрямах після того самого вирівнювання не нижчий за 20 дБ. Канали оцінюються окремо, береться найменше значення.
- **Відео:** однакові розміри; відносне відхилення тривалості не перевищує 0,02; SSIM не нижчий за 0,90 на наперед заданій кадровій сітці.

Для ненульових тривалостей використано симетричне відносне відхилення `dT = 2 × |T₁ − T₂| / (T₁ + T₂)`. Метрики вмісту застосовуються лише до наданого результату після повного декодування. Ненадання не зараховується як виконання критерію якості. Відсутня оцінка має значення `null`/`ND`, позитивна нескінченність — явне текстове позначення.

Початковий стереозразок WAV PCM16 із частотою 48 кГц перевищив ліміт бітрейту профілю `dissertation` — 1024 кбіт/с. Спостереження збережено як окрему перевірку S5 із очікуваним ненаданням. Для вимірювання якості в межах політики використано WAV PCM8 із тими самими частотою, каналами й тривалістю; пороги якості не змінено.

Компактний WebP зі згенерованим градієнтом також залишено як S5: вхід на 162 байти утворює PNG на 2081 байт і перевищує допустимий коефіцієнт збільшення 8. Для позитивного контролю WebP окремо задано генератор із фіксованим початковим станом; ресурсну відмову не вилучено з результатів.

## Повторення серії

Потрібні Rust/Cargo, PowerShell 7, FFmpeg і ffprobe. З кореня репозиторію:

```powershell
$env:MDO_TEST_FFMPEG = (Get-Command ffmpeg).Source
$env:MDO_TEST_FFPROBE = (Get-Command ffprobe).Source
pwsh -File ./scripts/test-dissertation.ps1
```

Можна передати унікальне ім’я: `-RunName windows-control-01`. Сценарій не перезаписує наявний запуск. Виконуються всі звичайні тести workspace та чотири окремі перевірки із зовнішніми компонентами. Генератор архівних тестових файлів залишається пропущеним. Код сценарію: [`test-dissertation.ps1`](../scripts/test-dissertation.ps1).

Кожен запуск створює папку `validation/runs/<ім’я>/`:

| Файл | Вміст |
|---|---|
| `README.md` | Підсумок виконання та перелік сценаріїв |
| `results.json` | Час, версії середовища, команди, коди завершення, повні виміри та SHA-256 входів/виходів |
| `cases.csv` | Ті самі контрольні записи у табличному вигляді |
| `*.log` | Виведення кожної тестової команди, включно з помилками |
| `SHA256SUMS` | Контрольні суми всіх файлів звіту |

У `results.json` зафіксовано Git-ревізію до запуску й окремий геш фактично перевірених вихідних файлів. Для текстових джерел перед обчисленням `sha256_lf` закінчення рядків CRLF замінено на LF; так зміна середовища не підміняє зміну коду. Геш агрегату обчислено з відсортованих рядків `геш␠␠шлях`, розділених LF. Зміни звітів не входять до цього агрегату.

CI запускає ту саму процедуру на Linux. Артефакт **`dissertation-evidence-Linux-X64`** зберігається 90 днів, включно з невдалими спостереженнями. Звичайні тести додатково виконуються на Windows і macOS. Локальні результати зберігаються у Git окремим знімком; CI не переписує їх і не робить автоматичних комітів.

## Межі висновку

Новий набір перевіряє конкретні переходи й критерії на згенерованих зразках. Він не замінює описані в рукописі:

- планову основну серію на 769 записів та її квоти з відкритих джерел;
- контрольний реєстр на 523 сценарії;
- описовий корпус на 492 об’єкти, у якому 262 результати надано, 232 виконали критерії вмісту, а 30 їх не виконали;
- порівняння 96 зображень за чотирма варіантами оброблення та трьома спробами;
- методику Q6 із класами розмірів, окремими сеансами й повторними вимірюваннями ресурсів.

Застосовні регресії частково покривають тематику S7; десять первинних випадків із дослідницького реєстру тут не реконструйовано. Абляції Q5 не заявляються виконаними. Повторюваність PNG не означає побайтової нерухомої точки для втратного MP3 або H.264. Етап успішного повторного читання не замінює відсутній у публічному API лічильник спожитих байтів. Час тестових команд включає складання й не є виміром продуктивності Q6.

Оригінальні медіафайли та результати у додатку В рукопису зазначено як серверний комплект. Для повторення тих числових результатів потрібні саме його вхідні файли, еталонний реєстр і зафіксоване середовище.
